Project Specification: Verifai
Goal: Build Verifai - a browser-based automated website crawler that generates test cases using AI (Generative UI Testing).

Core Product: Verifai is a tool that crawls a target website, maps its UI structure into a visual graph, and then uses Generative AI to automatically create test cases based on the visual structure.

User Roles
1. Admin: Can manage user accounts, permissions, and view usage analytics. Not directly involved in the crawling workflow.
2. Standard User (Tester): The main persona who will use the crawler to test their websites.
3. Target Application User: The end-users of the websites that are being crawled and tested.

Business Context
Manual UI testing is time-consuming and often repetitive. Teams need to ensure their web applications are accessible and functional across different devices. Verifai automates this process by using AI to understand the visual structure of a website (including interactive elements like buttons, forms, and links) and then generates comprehensive test scenarios to ensure the site works as expected.

The system must be able to:

Authenticate and manage users
Create and manage "Projects"
Crawl websites (Target Applications)
Map the UI structure into a visual graph
Generate test cases based on the UI graph
Execute and display the test cases

Key Features
1. User Authentication & Role Management
Description: A standard authentication flow for Standard Users and Admins.
Standard User: Can access the dashboard, create projects, and view test results.
Admin: Can view usage analytics and user management screens.
Implementation Details: Separate authentication for Standard Users and Admins. Admins should have additional screens for analytics.

2. Project Management
Description: The central hub for organizing crawling activities. A project represents a specific website or application that needs to be crawled and tested.

Functionality:

Project Creation: Users must provide a URL, target username, and password (if needed to access the site).
Project Details: Each project should have a unique identifier and a name.

3. Automated Website Crawling
Description: A core feature that explores the website to discover its pages and structure.

Trigger: Initiated by the Standard User.
Process: The system automatically navigates through the website, following links to discover all reachable pages. It should handle complex navigation patterns, including logins and authenticated sections.
Technical Implementation: Use Playwright for automated browser control.

4. Visual UI Mapping
Description: Converts the crawled website into a visual representation of its structure.

Output: A graph where nodes represent pages (or distinct UI states) and edges represent actions (e.g., button clicks, link navigations) that connect these pages.
Interaction: Users can view this graph to understand the website's layout and flow. Users can select a specific node to regenerate test cases for that particular page.

5. Generative UI Test Case Creation
Description: Uses AI to generate test cases based on the visual UI map.

Input: The generated UI graph and the original credentials (if used during crawling).
Output: A list of structured test cases that can be used to verify the website's functionality and accessibility.

6. Test Results
Description: After test cases are generated, users can execute them to identify issues.

Execution: Run the generated test cases using Playwright to verify they pass or fail.
Display: Show the results in a clear, actionable format, indicating which test cases passed and which failed.

Technical Requirements
Core Stack:
Frontend: Angular (Reactive Forms, Standalone Components) or React/Next.js (recommended for dynamic UI). Use TypeScript.
Backend: NestJS (Node.js) for REST API and modular architecture. Use TypeORM for data.
Database: PostgreSQL for structured data (Users, Projects, Credentials).
Crawling: Playwright for browser automation and screenshot capabilities.
Encryption: AES-256-GCM for sensitive data (passwords) and bcrypt for user credentials.
Authentication: JWT for secure API access.
UI State: Use BehaviorSubject (RxJS) for managing complex UI states (e.g., the crawling graph, test case lists).
Layout: A main shell with a sidebar (for navigation) and a main content area (for showing graphs and test results).

Data Model:

Users: Stores user credentials and role information.
Projects: Stores the target website's URL, username, and password.
CrawlRuns: Tracks the status of each crawl (e.g., Queued, Running, Completed).
UiNodes: Represents a single screen or distinct UI state discovered during crawling.
UiEdges: Represents the transitions (actions) between UiNodes.
GeneratedTestCasePrompts: Stores the prompts used to generate test cases.
GeneratedTestCases: Stores the test cases that were generated, including their status (Pass/Fail).
Additional Notes
Accessibility: Ensure the frontend is accessible, providing clear focus states for keyboard navigation.
Error Handling: Provide user-friendly messages for failed crawls or authentication issues.
Performance: Optimize crawling to avoid unnecessary requests and handle large websites efficiently.
Security: Secure storage of credentials and proper use of JWT tokens.
